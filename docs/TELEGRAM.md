# Трекер в Telegram: Mini App и бот

Бот: **@time_trackerr_bot** (заведён 05.08.2026). Настроено и работает целиком:
секреты записаны, функции выкачены, вебхук с расписанием подключены.

## Что это даёт

- Трекер открывается прямо в Telegram кнопкой из бота, без браузера и без
  ввода почты с паролем: человека опознаёт сам Telegram.
- Свой аккаунт подхватывается: кто уже вёл трекер на сайте, один раз вводит
  почту с паролем — и весь прогресс переезжает в Telegram (см. ниже).
- Бот напоминает о забытом таймере: «идёт уже 4 часа» — с кнопкой
  «Остановить» прямо в чате.
- Команды в чате: `/status` — что идёт сейчас, `/stop` — остановить,
  `/mute` — не напоминать, `/unmute` — напоминать снова.

Сайт при этом остаётся сайтом: в обычном браузере всё работает как раньше,
со входом по почте.

## Свой аккаунт: как прогресс попадает в Telegram

Telegram опознаёт человека сам, но НЕ знает, что тот уже вёл трекер на сайте:
при первом открытии Mini App заводится отдельный служебный аккаунт
(`tg<id>@telegram.local`), и накопленных часов в нём, разумеется, нет. Поэтому
первым делом Mini App показывает экран **«Уже вели трекер?»**: человек вводит
почту с паролем от своего аккаунта — и

- этот Telegram привязывается к нему навсегда: дальше каждый запуск открывает
  именно его, уже без почты и пароля;
- всё, что успело накопиться в служебном аккаунте, переезжает следом:
  одноимённые категории сливаются, остальные переезжают станциями, а если на
  карте заняты все шесть мест — уходят в архив (не теряются);
- пустой служебный аккаунт удаляется.

Кто действительно тут впервые — жмёт «Я тут впервые — начать с нуля», и больше
его не спрашивают. Передумал или хочет пересесть на другой аккаунт — кнопка с
человечком в правом нижнем углу карты (на её месте в браузере «выйти»).

Проверять подпись Telegram может только сервер, поэтому привязку делает
`telegram-link`: она требует ДВА доказательства сразу — подпись Mini App и
сессию того аккаунта, к которому привязываются (то есть знание пароля). С одной
подписью можно было бы присвоить чужой аккаунт, с одним паролем — привязать к
нему чужой Telegram.

## Секреты

Четыре строки в `tt_app_secrets`: `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_WEBHOOK_SECRET`, `REMINDER_SECRET`, `APP_URL`. Записаны, менять их не
нужно — разве что при смене бота:

    insert into public.tt_app_secrets (key, value) values
      ('TELEGRAM_BOT_TOKEN', 'токен от BotFather')
    on conflict (key) do update set value = excluded.value, updated_at = now();

> **Копируйте только сам запрос.** Если скопировать вместе с обрамляющими
> кавычками-ёлочками из markdown (` ``` `), SQL Editor ответит
> `syntax error at or near "```"` — он видит их как часть запроса.

Читать эту таблицу может только сервер: RLS включён, политик нет ни одной, и
для anon с authenticated её как будто не существует. Ключи в браузер не
уезжают — с ней работают лишь Edge Functions под сервисным ключом.

Кто предпочитает штатный путь — те же значения можно задать как секреты функций
(панель Supabase → Edge Functions → Secrets, или `supabase secrets set`). Код
смотрит туда в первую очередь и берёт таблицу только как запасной вариант.
**Но** расписание напоминаний читает `REMINDER_SECRET` именно из таблицы, так
что его строку оставьте в ней в любом случае.

## Выкатили новую версию — а в Telegram старая

Telegram кэширует страницу Mini App по адресу и держит её долго, а кнопки
«обновить» у человека нет. Поэтому в `APP_URL` на конце стоит `?v=N`: меняем
цифру — адрес становится новым, и webview тянет свежую страницу.

    update public.tt_app_secrets
    set value = 'https://time-tracker-7ux.pages.dev/?v=3', updated_at = now()
    where key = 'APP_URL';

Ту же цифру надо поставить и кнопке меню (её адрес живёт у Telegram, не у нас):

    curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setChatMenuButton" \
      -H 'Content-Type: application/json' \
      -d '{"menu_button":{"type":"web_app","text":"Трекер","web_app":{"url":"https://time-tracker-7ux.pages.dev/?v=3"}}}'

Со стороны сайта помогает `public/_headers`: `index.html` отдаётся с
`no-cache`, а файлы в `assets/` — навечно (у них хеш в имени).

## Проверка после настройки

1. Открыть бота → `/start` → нажать «Открыть трекер». Должна открыться карта
   без экрана входа.
2. Запустить таймер на станции, свернуть Telegram, в чате написать `/status` —
   бот должен ответить, что идёт, и сколько.
3. `/stop` — таймер останавливается, в приложении время записалось.
4. Напоминание: в SQL Editor сдвинуть начало своей сессии на пять часов назад
   (`update tt_sessions set started_at = now() - interval '5 hours' where ended_at is null;`)
   и подождать ближайшего получаса — или дёрнуть функцию вручную с секретом
   напоминаний в заголовке `x-reminder-secret`.

Если бот молчит: `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo` покажет
`last_error_message`. Логи функций — в панели Supabase, раздел Edge Functions.

## Если понадобится переставить связку руками

Обычно это делает сам человек экраном «Уже вели трекер?» (см. выше), но из SQL
тоже можно — например, когда пароль от старого аккаунта забыт:

    update public.tt_telegram_links
    set user_id = (select id from auth.users where email = 'почта старого аккаунта')
    where telegram_id = <telegram_id>;

Данные при этом НЕ переезжают — переносит их только `tt_link_telegram`, то есть
экран в приложении. И человеку надо будет заново открыть Mini App: пока он не
перезапустит его, в приложении останется прежняя сессия.

## Как это работает

**Вход.** Mini App отдаёт функции `telegram-auth` строку `initData`, которую
Telegram подписал ключом бота. Функция проверяет подпись (без токена бота её не
подделать), находит аккаунт по `telegram_id` или заводит новый и возвращает
обычную пару токенов Supabase. Дальше приложение живёт как после входа по
почте — те же данные, те же правила доступа к строкам.

Обмен идёт при КАЖДОМ запуске, а не только когда своей сессии нет: подпись
Telegram здесь источник истины. Аккаунт, к которому привязан этот Telegram, мог
смениться (экраном «Уже вели трекер?»), а сохранённая сессия переживает
перезапуск и держала бы человека в прежнем.

**Напоминание.** Раз в полчаса планировщик дёргает `telegram-remind`. Та
спрашивает у базы (`tt_forgotten_timers`), у кого прямо сейчас идёт сессия
дольше его порога — по умолчанию 4 часа — и кому не писали последние 6 часов.
Таким уходит сообщение с кнопками «Остановить» и «Пусть идёт». Нажатие
«Остановить» приходит вебхуком в `telegram-bot`, и тот закрывает сессию
серверной функцией `tt_stop_session_for` — ровно так же, как это делает кнопка
«Стоп» в приложении.

Порог у каждого свой и лежит в его строке `tt_telegram_links.remind_after_minutes`
(по умолчанию 240). Выключить напоминания насовсем — `/mute` в чате.

## Если понадобится переподключить бота

Заменить секрет вебхука (после смены значения в `tt_app_secrets`):

    curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
      -H 'Content-Type: application/json' \
      -d '{"url":"https://tnuyvummwzmucuezirtu.supabase.co/functions/v1/telegram-bot","secret_token":"<секрет>","allowed_updates":["message","callback_query"]}'

Снять расписание напоминаний: `select cron.unschedule('tt-forgotten-timers');`
